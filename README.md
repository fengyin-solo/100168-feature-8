# 机场地面保障调度平台

面向机场机坪运行的航班保障、机位资源、廊桥对接、除冰加注、行李装卸与保障结算的一体化地面调度后台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 机坪巡查闭环

机坪巡查单的状态序列为：待派发 → 巡查中 → 已提交 → 已整改（已作废为负向终态，
待派发、巡查中、已提交阶段都可作废，且不能重复作废），状态只进不退、不允许回到前一段：

1. **派发巡查**：待派发 → 巡查中。
2. **提交结果**（仅巡查中可执行）：`values.问题明细` 按巡查项目逐项登记
   `{巡查项目, 发现问题数}`；发现问题数空缺、非整数或为负数时拦截报错，失败尝试仍写入
   该巡查单的 `操作留痕`。问题数大于 0 的项目自动生成带 `事项编号` 的待整改事项，
   问题数为 0 的项目不生成事项。
3. **回填整改**（已提交阶段可执行）：`values.整改明细` 逐条回填
   `{事项编号, 整改结论, 整改人}`，整改结论与整改人缺一不可；同一条巡查单重复提交
   整改结论只保留最后一次。
4. **完成整改**（已提交 → 已整改）：仍有整改结论未回填的事项时不允许流转到最终状态；
   零问题巡查单停留在已提交，无需完成整改。
5. **按区域汇总**：`GET /api/apron/summary` 按巡查区域汇总发现问题数、待整改数与
   已整改数，支持与列表相同的 `keyword`、`status`、`area` 过滤，汇总口径与列表
   完全一致（同一套筛选、同一份内存数据），刷新后仍成立。
6. **明细与留痕**：`GET /api/apron/{id}` 返回 `待整改事项` 与 `操作留痕`
   （成功、失败尝试都留痕）。派发巡查、作废巡查动作继续可用。

回归测试：`cd backend && python3 tests/test_apron.py`。
